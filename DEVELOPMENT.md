# Development

## Prerequisites

| Tool | Version | Needed for |
| --- | --- | --- |
| Node.js | 20+ (developed on 24) | everything |
| Xcode + iOS 16.4 SDK | 16+ | building the example on iOS |
| CocoaPods | 1.15+ | iOS native dependencies |
| Android SDK + JDK | API 34+, JDK 17+ | building the example on Android |

You only need Xcode or the Android SDK for the platform you intend to run. The TypeScript layer,
tests and the config plugin need nothing but Node.

## Getting started

```sh
npm install          # `prepare` also builds build/ and plugin/build/
npm test             # 44 tests
```

## Scripts

| Script | What it does |
| --- | --- |
| `npm run build` | Clean + full build: `src` → `build/`, `plugin/src` → `plugin/build/`. One-shot. |
| `npm run build:watch` | `tsc --watch` for `src` only. Consumed by Metro while developing. |
| `npm run clean` | Removes `build/` and any subtarget output. |
| `npm test` | Jest across `src` and `plugin/src`. |
| `npm run typecheck` | `tsc --noEmit` over `src` + `plugin/src`, **including tests**. |
| `npm run lint` | ESLint over `src` and `plugin/src`. |

`build` and the npm `prepare` lifecycle point at the same script, so `npm install`, `npm pack` and
`npm publish` all produce a fresh build. Note that `prepare` wipes `build/` first — if Metro is
running against the module, expect a brief resolution error during a rebuild.

## Layout

```
src/                    TypeScript public API
  uri.ts                  pure anyconnect:// builders + callback parser
  transport.ts            AnyConnectTransport + UriHandlerTransport
  CiscoAnyConnect.ts      facade: state machine, events, deep-link wiring
  CiscoAnyConnectModule.ts native binding (optional import)
  CiscoAnyConnectError.ts  error codes
  useAnyConnect.ts        React hooks
ios/                    Swift module — UIKit URL APIs only
android/                Kotlin module — PackageManager + ConnectivityManager
plugin/src/             config plugin
example/                runnable demo app
internal/module_scripts vendored build/test/open helpers (not published)
```

Architecture and the request/callback flows are documented in
[docs/architecture.md](docs/architecture.md).

## Iterating on native code

The example app consumes the module through `file:..`, so it needs `build/` to exist:

```sh
npm run build            # repo root, once
cd example
npm install
npm run ios              # or npm run android
```

Workflow for a change that spans JS and native:

1. **JS only?** `npm run build:watch` in one terminal, `cd example && npm start` in another. Fast
   reloads, no native rebuild.
2. **Native?** Rebuild the example (`npm run ios` / `npm run android`). Autolinking picks up the pod
   / Gradle module from the parent directory, so no `pod install` is usually needed — but after
   adding a *file* to `ios/` or `android/`, re-run the build so autolinking regenerates.
3. **Config plugin?** Plugin output is applied at prebuild:

   ```sh
   cd example && npx expo prebuild --clean && npm run ios
   ```

   Inspect what it produced: `plutil -p example/ios/*/Info.plist` and
   `grep -A12 '<queries>' example/android/app/src/main/AndroidManifest.xml`.

Debugging tips:

- Log the exact URI that was dispatched (`AnyConnectDispatchResult.url`) and compare it against
  [docs/api.md](docs/api.md) — malformed URI is a common self-inflicted failure.
- Verify the URI by hand before blaming the module:

  ```sh
  adb shell am start -a android.intent.action.VIEW -d "anyconnect://connect/?host=vpn.example.com"
  ```

  A matching adb logcat entry after dispatching means routing works; silence means URI External
  Control.
- On iOS, `console.log(CiscoAnyConnect.getCallbackScheme())` tells you whether a callback can route
  back at all.

## Testing

| Suite | Covers |
| --- | --- |
| `src/__tests__/uri.test.ts` | The exact `anyconnect://` wire format and encoding quirks. |
| `src/__tests__/CiscoAnyConnect.test.ts` | State transitions, event emission, scheme resolution, and behaviour with no native module (Expo Go / web). |
| `plugin/src/__tests__/plugin.test.ts` | The config plugin, run through Expo's real mod chain, asserting the resulting `Info.plist` / `AndroidManifest`. |

Jest roots are configured in `package.json` (`<rootDir>/src`, `<rootDir>/plugin/src`). Tests are
excluded from the build configs so they never land in `build/` or `plugin/build/`.

### What is not covered

**The Kotlin and Swift are not compiled by CI.** There is no Xcode project or Gradle build for the
module in isolation — those are generated by `expo prebuild` in a consuming app. Currently the native
code is only syntax-checked, via:

```sh
for f in ios/*.swift; do xcrun swiftc -parse "$f"; done
```

Behaviour is exercised through `example/`. If you touch native code, run the example on a device
before opening a PR, and say so in the PR description. Adding a CI job that prebuilds the example and
compiles both platforms would be a welcome contribution.

**The React hooks are not unit-tested.** No renderer is installed (`@testing-library/react-native`
would be the addition), so `useAnyConnect` and `useAnyConnectCallback` are thin wrappers over the
facade, which *is* tested. Adding a renderer and covering them is a good first contribution.

## Adding a new action

Cisco's URI handler is the only surface, so a new action is usually a small, mechanical change:

1. **Builder** — add a function in `src/uri.ts` (pure, no native dependency).
2. **Test** — add a case in `src/__tests__/uri.test.ts` pinning the exact string.
3. **Transport** — add the method to the `AnyConnectTransport` interface and to
   `UriHandlerTransport`.
4. **Facade** — expose it on `CiscoAnyConnect`, calling `ensureInitialised()` first.
5. **Export** — add it to `src/index.ts` if it is a helper users should reach.
6. **Docs** — add a row to the URI reference table in `README.md` and a section in `docs/api.md`.
7. **Changelog** — add an entry.

Only add a native method when the OS itself must be involved (availability, dispatch, state,
capture). Everything protocol-shaped belongs in TypeScript, where it is testable.

## Code style

- Prettier config is in `.prettierrc`; ESLint is `eslint-config-universe`. Run `npm run lint`.
- Public API gets JSDoc, including *why* a platform quirk exists — not a restatement of the name.
- Prefer describing a limitation honestly over returning a plausible guess. The iOS state behaviour
  is the reference example of this.
- Errors thrown from the public API are `CiscoAnyConnectError` with a stable code. Do not add a code
  without documenting it in `docs/api.md`.

## Releasing

1. Bump `version` in `package.json`. That is the single source of truth — the podspec reads it, and
   nothing else hardcodes a version.
2. Add a `CHANGELOG.md` entry under the new version.
3. Confirm the gate is green:

   ```sh
   npm run typecheck && npm run lint && npm test && npm run build
   ```

4. Inspect exactly what will ship:

   ```sh
   npm pack --dry-run
   ```

   Expect no `__tests__`, no `tsconfig*`, no `example/`, no `internal/`, and to see `build/`,
   `plugin/build/`, `app.plugin.js`, `expo-module.config.json`, `ios/`, `android/` and `docs/`.

5. Update `repository`, `homepage`, `bugs` and `author` in `package.json`, plus `s.source` in
   `ios/CiscoAnyConnect.podspec`, if they are still the placeholders. Replace the copyright holder in
   `LICENSE`.
6. `npm publish`.
